# 完全分類アトラスの設計 — 2026-11-16 / v22

## 目的と現在の確実性

対象は標準14641型の四次元quadratic Koszul AS-regular indexed Z-algebra、
同値は添字保持同型とする。最終成果は族の羅列ではなく、
**全対象の被覆定理、各枝の正規形・全同型判定・特殊化関係**を備えた分類である。
以下は研究方法の設計である。現在、第三のテンソル行列階数による二分岐の被覆のみ証明した
（`sections/frobenius_tensor.tex:prop:opposite-rank-split`）。
最小の現行枝データは `research/classification_branches.json` に置く。
各子枝の一般正規形・Koszul/AS判定・完全同型は未解決であり、設計自体をそれらの証明と見なさない。

標準Frobenius四周期の四窓表示では、各 V_i は4次元、各 R_i は
V_i⊗V_{i+1} 内の6次元関係空間であり、表示データは四つの
Gr(6,16) に属する。GL(V_0)×…×GL(V_3) が基底変更として作用する。
四窓へ還元できることと、この全表示空間内でAS正則locusを完全決定したことは別である。
標準4周期の選択、添字保持同型、周期構造付き同型を混同しない。

## 研究の主経路

1. **全体を固定する**：四窓のAS/Koszul必要十分条件を探し、既知の
   Frobenius有限条件と未解決のKoszul条件を区別する。
   構造定理を優先し、巨大な消去計算を最初から全空間へかけない。
2. **構造的な分類木を作る**：添字保持同型で不変なrank、テンソル分解、
   双対の中心・Nakayamaデータ、点/線スキームなどから枝を選ぶ。
   それぞれの切断条件と親枝の被覆（枝の和が親に等しいこと）を証明する。
   point scheme等は非完全不変量になり得るので同型の十分判定には使わない。
3. **枝ごとに正規形を与える**：有限型パラメータ空間、分母が非零という条件、
   特殊値、正則性、同型の残余群作用を明記する。
   一般パラメータの計算で零となった判別式の枝を捨てず、例外枝として記録する。
4. **同型を安く検査する**：計算の軽いGL不変量で候補を絞り、
   正規形の安定化群と許容変数変換を調べる。最後にだけ一般の
   212未知数388式の有限同型判定を使う。
   特徴量の不一致は除外証明となり得るが、一致だけで同型とはしない。
5. **特殊化を接合する**：パラメータの例外境界、他の正規形への基底変換、
   軌道閉包の包含、全正則locusにおける成分性を別々に証明する。
   ある族が別族の閉包に入っても、一般ファイバーの同型や成分一致を推論しない。
6. **証明されたデータから分類表を生成する**：本文の表を手入力の正本にしない。
   数学的証明がある枝だけ確定分類として表示し、未解決枝を明示する。

## 分類木と成果の最小単位

「1例」や「既知族」ではなく、**条件を持つ分類枝**を単位にする。
各枝に安定したIDを与える。少なくとも次の情報を管理する。

- 親枝と所属述語：親領域のどの部分を扱うか、選んだ不変量の同型不変性
- covering claim：親を子が覆うという主張、証明箇所、未証明ならその旨
- 正規形と基底：四窓の全関係式、パラメータ条件、分母、特殊値、入力源
- 正則性：全パラメータかgenericのみか、左右Koszul/AS証明、未解決除外領域
- 同型条件：必要条件と十分条件を分離し、許容変換と残余安定化群を記録
- 周期：最小周期1/2/4の証明された領域と判定不能領域を分離
- 交差と退化：他の枝への同型・包含・特殊化、正則性維持の条件と証明
- 検証：論文の定理ラベル、再現用入力・コード・証明書、文献と新規性の状態

状態は一つの「完了フラグ」にせず、
**構成、AS正則、被覆、同型必要十分、境界接合、周期、文献照合**
を独立の証明義務とする。例えば現行九変数族はAS正則・一般周期は証明済みだが、
全対象の被覆・成分最大性・完全同型は未完成である。
既知の結果を「分類済みの枝」と誤登録しない。

親枝の被覆は機械的な件数合計ではなく、数学的に
（親の各点はいずれかの子に属する）と証明する。
兄弟枝は重なってもよい。その場合は交差と同型条件を記載する。
分類木は包含・特殊化の有向グラフとは別に管理する。

## 巨大化に耐える研究基盤（nc-p3自体がas4より大規模になる場合）

分類表だけではなく**研究ソース全体が巨大化**することを前提とする。
大きくなったときの律速は、全資料を探す、全内容を読み込む、
一つの証明の変更がどこに影響するか調べる、全計算を再実行する、
同じ結論を多くの文書に書き直すことにある。容量上限で数学を削らず、
各作業の読込・変更・検証範囲を局所化する。

### 三層の知識アクセス

1. **小さな入口（常時）**：研究方針に最終目標・達成基準・最優先の未被覆領域・
   具体的な次の一手を置き、AGENTSには実行規則だけを書く。
   現行STATEは当面主張・課題索引だが、肥大化したら現行の短い
   active index + 各分野の索引に分割する。
   索引はID、命題の要約、状態、正本のパスを指し、証明本文や巨大な式を保持しない。
2. **対象モジュール（作業時）**：四窓の全条件、構造分岐、
   正規形、族内外同型、周期層、境界と成分などを、数学的に独立して
   作業可能な単位に分ける。各単位には短い入口・安定した主張ID・
   主要な未解決義務・依存する他モジュールへの参照を持たせる。
   一つの問題を扱うCodexは当該モジュールと直接必要な定理だけ読む。
3. **詳細な証明・計算（必要時）**：日本語LuaLaTeXの論文・補題の完全証明、
   コード、原始入力、再現手順、必要な証明書を現行版として保持する。
   起動時や無関係の枝の作業時には全読込しない。
   既存内容は分割の都合だけで削除・要約しない。

これはデータを「過去資料」として倉庫化する方式ではない。
三層とも**現行研究**であり、古いZIP・重複原稿・作業履歴を保存するための層ではない。
単独の最新mainから再開でき、過去会話や外部の旧版は不要とする。
外部as4はBASELINEの限定した依存索引だけを通常読込み、同じ境界を越えない。

### 二つの有向依存グラフ

- **分類の被覆・退化グラフ**：各分類枝に安定IDを振り、
  親の領域を子が尽くす証明、枝の交差、同型の重複、境界特殊化を管理する。
  「親子の被覆」と「族間の特殊化」を別の関係として記録する。
  兄弟枝が重なることを許し、等号と包含を分ける。
- **数学的依存グラフ**：主張IDを、必要とする定理、対象定義、計算コード、
  既知の文献結果、入力・証明書、検証手順に結びつける。
  訂正時には逆依存を辿り、影響した主張と要約・方針・論文を再評価する。
  証明本文を索引に重複させず、TeXの安定ラベルと現行ファイルパスを使う。

一つの巨大なモジュライ図や局所計算は全分類の完了を意味しない。
各枝の「全対象を覆う」「正則」「同型必要十分」は独立の義務として保持する。

### ファイル分割と正本の単一化

最初から全枝の空ディレクトリや数百個の雛形は作らない。
最初の本格的な網羅分岐が証明され、単一ファイルでの参照や検証が
負担になった時点で、例えば `classification/<branch-id>/` 以下に
枝ごとの機械可読な条件・証明参照を置く。
主張索引も同様に分野・依存単位ごとへ分割し、ルートには最優先の状態と
検索用の小さな目次のみ残す。外部から同じ結果を二重の正本として持たない。

公表論文は、論理的なまとまりに応じてTeXソースを章・節単位に分割し、
必要なら複数論文にする。各論文は独立した中心結果と完全な証明を持つ。
巨大な分類表は機械可読な一つの正本から生成し、
本文の簡約表と詳細表を人手で別々に維持しない。
変更履歴・旧版・重複する説明を蓄積する代わりに最新の説明へ統合する。

### 局所的な検証と再現可能性

共通の四窓判定、正規形、同型フィルタ、証明書チェッカーは
再利用可能な**小さな共通モジュール**として設計する。
枝ごとの計算は入力と出力の対応、依存する定理・ソフトウェア、
判定範囲を記録し、同じ計算を別実装で反復しない。
通常は変更した対象と逆依存だけを再実行し、
大きな変更・配布前の節目では必要な全域回帰試験を実施する。
部分検証しか行っていない場合は明記する。

有限体標本・数値階数は探索であり、一般の分類定理は
厳密計算の証明書または構造的証明を必要とする。
重い計算の中間キャッシュをGitで追跡せず、必要な大容量入力・証明書は
再生成不能性と検証方法を説明して現行の必要資産として保持する。
外部保存や別repoへの分割が必要になる場合は、元の再現可能性と
参照の永続性を損なわない設計を先に検証する。
GitHub Actionsに依存しないローカル検証を維持する。

### Codexの一作業・一再開の単位

着手時は短い研究方針 → 現在の未被覆の最優先枝・主張ID →
その正本ファイル → 必須の直接依存、の順に開く。
**原稿一式、全ノート、全as4、全Git履歴、全枝の全面スキャンを標準手順にしない。**
一作業の終了時には、解決した証明義務・残った最小の穴・次に読む正本パスを
小さな現行索引と方針に統合する。研究作業実況や時系列変更記録を残さない。
困難な枝で停滞した場合、局所研究から別の未被覆枝や構造的不変量へ切り替える。
Cloud Codexで実際に一つの数学的作業が終わっても、
分類完了・実際の利用上限・不可避の障害に達していなければ、
次の証明義務へ自律的に進む。作業中の約15分ごとの安全な保存は
意味のある更新がある場合に限り、途中結果の状態を誤って定理にしない。
終了前には`research/STATE.json`の`resume_point`を現行の次の一手に更新し、
次のCloudタスクが旧会話・未コミット作業に依存せずに再開できるようにする。
実行枠やCloudのタスク間自動起動はAGENTSで保証されないことを明示する。

### 段階的に導入する順序

- **今**：方針と指示を短い入口に保ち、既存の論文・ノート・コード・35主張の
  所在を維持する。最初の網羅的分岐を証明する研究に資源を集中する。
- **分類枝が実在した時**：安定枝ID・被覆義務・枝の条件・参照を
  最小限のデータとして導入する。表の生成もその時始める。
- **依存や計算が複雑化した時**：主張依存・逆依存と差分検証を導入し、
  既存の検証・コードを移行する。肥大化した索引を分割する。
- **多数の枝・論文になった時**：分野別の入口、複数論文、
  詳細分類表の生成、回帰試験選択を整える。
  いずれも数学的内容や再現可能性を犠牲にするための固定容量制限を置かない。

**各段階の導入条件は、実際の探索・検証・原稿更新が律速になったこと。**
現段階で空の巨大な管理システムを作るのは避ける。

## 計算と表の拡張方式

**今は新しい巨大な登録簿を作らない。** 現行の research/STATE.json は主張と
課題の索引として保持する。最初の非自明な「親を覆う」場合分けが証明された時点で、
その枝を最小の1件として記録し、必要なJSON schema・検査器・表生成器を導入する。
その時からデータを1枝1ファイルとし、原稿に同じ表を転記して手修正しない。

将来のレコードは例えば branch_id, parent_id, membership_condition,
parameter_scheme, normal_form_ref, regularity_ref, cover_ref,
isomorphism_ref, period_ref, boundary_edges, status_by_claim,
verification_refs とする。
式・定理・証明をJSONに複製せずTeXへの安定したラベルで参照する。
枝数やページ数に固定上限を置かない。

計算では、厳密な有理数・代数数を最終証明に使う。
有限体標本やランダム階数は候補発見・反例探索に使い、一般命題には
記号的小行列式、飽和イデアル、構造的証明などの証明書を付ける。
追加の枝だけ再計算するインクリメンタル検証とし、
既に証明済みの共通補題を毎回計算し直さない。
例外パラメータ（分母ゼロ、判別式ゼロ）を未分類のまま消去しない。

分類表は必要に応じて「短い公表用」「完全な検索用」の二表示を生成する。
論文は構造定理と代表的な族を理解しやすく示す本文を維持し、
大きな列挙は生成可能な表と証明参照で支える。
旧版・中間表・変更履歴・複製文献PDFは保持しない。

## 実際の着手と回帰試験

最初は四窓AS条件について、全対象に適用できる分岐不変量を一つ探し、
**分岐の網羅性の証明**まで追う。同時に量子多項式、Clifford点、
七・九変数楕円Ore族、五変数境界族、as4の最小周期4例を回帰試験入力とする。
as4は巨大な外部ライブラリと位置づけ、通常はnc-p3のBASELINEにある短い
固定blob付き依存索引のみ読む。新しい枝が既存結果に依存するときだけ
該当定理・仮定・証明・コードの必要範囲を取得し、毎回の全件同期はしない。
as4のAGENTS.mdや全研究資産を常時読み込んで分類を妨げない。
これらを全分類の完成した枝と見なさない。
外部の4d-AS-regularデータベース（https://4d-as.ncag.info/）には
gradedの既知族が族単位で記録されているので比較・回帰に使えるが、
indexed Z-algebraの網羅性を保証しない。
比較時は必要な出典と参照箇所だけを保持し、外部全件を無批判に複製しない。

Codexは各作業で「どの未解決の被覆義務を減らすか」を決めて着手し、
局所計算が長引けば別の構造的不変量や枝へ自律的に切り替える。
現行の証明や反例は必要な箇所へ統合し、研究ノートは作業ログにしない。
再開時は research/plan_ja.tex → 本設計 → 未解決の枝 → 必要な証明だけ読む。
GitHub mainを正本とし、再現可能なソースだけを保存する。
