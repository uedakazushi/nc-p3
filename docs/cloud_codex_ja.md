# nc-p3：Codex Cloud環境と研究タスク — 2026-11-16 / v21

この文書は**Cloud環境を作成・検査する手順**であり、GitHubへ保存するだけでは
Cloud側の環境を設定・公開したことにはならない。環境が存在するか、
接続されたGitHubアカウントにpush権限があるかはCloud側で確認する。

## Cloudで使うリポジトリと入口

- Codex Cloudで `uedakazushi/nc-p3` のmainを選ぶ。通常の環境には巨大な
  `as4` を一緒にチェックアウトしない。as4は `research/BASELINE.md` の
  固定した結果への参照から、必要時に対応部分だけ取得する。
- ルートの `AGENTS.md` がCodexの自動参照対象である。
  `START_CODEX_ja.md` は起動時に**明示して**読ませるための文書で、
  Cloudの「インストールスクリプト」でも自動実行ファイルでもない。
- 最上位目標は標準14641型の添字保持同型による完全分類。
  最初の研究課題は `Z4-AS-004` と `STRUCTURE-009`。
  四窓の全AS条件、網羅的な構造分岐を優先する。

## Cloud環境を作成・公開する

Codex Cloudの新しいタスクで **Work in > Cloud → Select environment →
Create environment** を選び、GitHubの当該リポジトリを指定する。
Codexの環境セットアップ画面で必要なツールをインストール・検証させる。
動作確認が済んだら **Publish** する。既存の環境を変更した場合は
**Republish** し、新規タスクからその版を使用する。

環境に必要なもの：

- Python 3（本研究の検算はPython 3.12とSymPy 1.14.0で再実行した実績がある）。
- `requirements.txt` の `sympy==1.14.0`。
- 日本語論文の組版用に `latexmk`、`lualatex`、LuaTeX-ja
  (`ltjsarticle.cls`, `luatexja-preset.sty`)、Harano Ajiフォント。
  Cloudの既定環境にこれらが存在するとは**仮定しない**。
- GitHubの読み書き権限。ただしCloudのリポジトリ接続と
  端末内の `git push` 権限は同じと限らない。Cloud側で動作を確認する。

Python環境・TeX環境のセットアップはCloudの環境準備会話でCodexに
行わせてよい。ネットワークアクセスが必要なら、取得先のドメインと
利用目的に限定して設定する。トークン、SSH秘密鍵、認証情報を
GitHubリポジトリへ保存しない。

## 軽量な環境確認

まずリポジトリのルートで以下を実行する。

```sh
bash scripts/cloud_preflight.sh
```

これでPython/SymPyバージョンとプロジェクト構造を確認する。
日本語LuaLaTeXをインストールした後に

```sh
bash scripts/cloud_preflight.sh --tex
```

を実行し、組版まで確認する。
`--tex` は既存の軽い研究方針を組版する。
定理・計算の検証が完了したという意味ではない。
本格的な検証は変更した内容に応じREADMEの該当コマンドで行う。
環境作成時に一度だけフル検証を試みる場合も、実行時間・失敗状態を
正直に記録し、タスクごとの再実行を自動的な義務としない。

## CloudタスクのGitHub保存

Cloudでは各タスクが独立した作業領域を持ち、新しいタスクは別のタスクの
未コミットの変更を引き継がない。そのため区切りごとに**意味のある内容を**
GitHubへ保存することを優先する。

- 研究開始時とpush前に `git fetch origin main` などで先端を確認する。
  他のタスクが先にpushしていれば、衝突を確認し数学的成果を統合する。
- 認証・権限が許す場合のみ、PRを作らず通常のfast-forwardで
  `main` へ直接pushする。force pushはしない。
  detached HEAD等の場合にどのcommitをpushするかは明示的に確認する。
- pushの拒否、認証不足、接続不可の場合は、**保存成功と報告しない**。
  実際にコミットできたものと未保存内容を区別し、ユーザーへ状態を報告する。
- 一作業・一区切りの終了時には、研究方針、現行索引、必要な論文・ノートと
  計算入力を整合させる。古いWIPログ・過去版・PDFをGitで追跡しない。
- Cloudの実行時間・ツール権限・利用上限はリポジトリの指示では変更できない。
  一つのタスクが完全分類の達成まで無期限に実行されるとは約束しない。

## 最初の研究タスクの例

「`AGENTS.md` と `START_CODEX_ja.md`、
`research/plan_ja.tex` の現在の最優先課題を確認し、
`Z4-AS-004` の未被覆部分を一つ減らす数学的仕事をしてください。
`as4` は固定した索引の必要な結果だけ読む。
証明・計算・反例を区別して現行原稿に統合し、
実行可能な検証をして、許可された場合はmainにfast-forwardでpushしてください。
Cloud環境の権限で不可能な操作は明示してください。」

## 設定画面で確認すること

Cloud環境の公開状態、PythonとTeXのツール、
GitHubとの接続、必要なら限定ネットワークアクセス、
作業時の書込権限を**環境のテスト結果で**確認する。
リポジトリ内のこの文書やAGENTSだけでは、Cloud環境が既に
公開・実行可能であることを保証しない。
